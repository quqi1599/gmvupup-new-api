# 模型监控

管理员从「使用日志 → 模型监控」打开。列表按模型看最终请求，展开模型可查看首包和生成速度趋势、各渠道尝试，点日志按钮进入同模型（可选同渠道）的最近 15 分钟日志。普通用户仍只能通过原接口查看自己的使用日志，能从已有日志字段看到单条速度。

界面参考 New API 新版：日志的「流」列显示流状态和输出速度，「耗时」列显示首字时间和总用时；监控顶部汇总当前筛选的模型，完成率按符合条件的请求数加权。仅更新这两处界面，保留旧后台导航和原接口。

- 日志速度 = 输出 token ÷ 整程用时。新日志优先使用毫秒数，历史整数秒耗时显示为估算；缺有效用时、无输出和异步任务不显示速度。
- 监控仅采集可识别启用模型的同步 Chat、Completions、Claude Messages、Responses 和 Gemini 文本生成。鉴权失败、在识别模型之前已被拦截的请求、后台任务、图片和嵌入入口不计入。无可用渠道记在模型的最终请求，不虚构渠道尝试。
- 完成率 = 完成 ÷（样本 − 客户端取消 − 请求拒绝）。正常限长单列，不记作断流或完整完成。已开流但缺终态、异常 EOF 与上游拒绝分开。一次最终请求可能对应多次渠道尝试。
- 首包是网关收到的首个有效流事件，不保证是用户看到的第一个正文 token。首包 P95 是完成或正常限长流的直方图桶上界；平均总用时也只用完成或正常限长样本。流式生成速度 = 有有效流式用量的输出 token 总数 ÷ 首包至结束的累计秒数。零样本显示「无样本」，不填零。
- 只写专用的 `model_performance_buckets`；不扫描历史 `logs`，不回填历史监控。5 分钟桶含当前未满的一桶，页面显示实际起止，正常每 30 秒保存。迁移和保存不在请求路径；写入失败重试快照，积压有硬上限。专用统计表保留约 7 天，旧数据分批清理。
- 如需关闭采集和页面数据接口，在部署配置设置 `MODEL_PERFORMANCE_ENABLED=false` 并重启目标进程。关闭不删已有统计，不影响日志和计费。
