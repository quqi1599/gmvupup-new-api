# 网页体验接入 CPA 的签名身份修复

2026-11-03，本地实现；未提交、推送或部署。

## 问题与改法

网页体验 `/pg/chat/completions` 使用已登录用户和临时 Token（ID 为 0）。原 CPA 身份协议只接受正式 Token 或管理员渠道测试，正常体验请求因此在 NewAPI 出站前返回 500。

新增专用 v2 网页体验身份：`X-CPA-Audit-Version: 2`、`X-CPA-Audit-Identity-Kind: playground`、真实正数用户 ID、Token ID 0、固定 Token 名 `__playground__`、非渠道测试，以及非空请求 ID。规范化签名串在原字段外加入 `identity_kind`，其余 method/path/model/timestamp/身份字段继续受 HMAC 保护。正式 API Token 和管理员测试保留原 v1 字节协议。

类型只由服务端已认证的网页体验入口生成；客户端或渠道覆盖传入的审计头先清除再重签。管理搜索的身份副本保留 IsPlayground，其搜索引用仍按 `user_id:token_id` 分隔。

网页体验的模型历史归属使用独立 `newapi/cpa-principal/playground/v1` 域，绑定站点地址和真实用户 ID；与正式 Token、其他用户及其他站点区分。若站点地址未配置、仍为 localhost 或无法派生身份，则在模型出站前明确失败，避免退回共享 CPA 凭据的历史归属。

钱包/订阅结算代码不修改：仍按已登录用户预扣、结算或退款，不创建虚假 Token，也不扣其他 Token 的额度。新旧 CPA 都必须验证该 v2 协议，并对网页用户继续执行内容审核；审计表复用用户 ID、Token ID 0 和固定名称，无数据库迁移。

## 本地验证

- 固定 HMAC 向量由独立实现生成，NewAPI 签出、新旧 CPA 验入。
- 真实 cookie 会话经过 UserAuth、Distribute、Playground、Relay 到本地模拟上游，覆盖普通响应及 SSE，校验线上协议的签名和用户历史归属。
- 未登录、用户头与会话不一致、未配置公开地址都不能发往模型；已有钱包预扣的失败路径需退款。
- 成功仅产生一条用户消费，真实 Token 的额度不变；上游拒绝恢复预扣。
- 验证端覆盖篡改、过期、未知类型、协议降级及旧 v1 兼容，正常内容放行、需要阻断的合成内容保持阻断。

模拟服务和 SQLite/Redis 测试数据均本地生成，不重放客户内容、不调用收费模型。本地测试不等同于 CI 或客户原网页恢复。

## 发布与回退次序

1. 先发布所有可能接收网页体验请求的新 CPA 和旧 CPA 验证端；验证原 v1 和新 v2 均可用。只升级新 CPA 会使旧后备收到 v2 后返回 401。
2. 再发布 NewAPI 签名端，核验真实站点地址配置及登录网页体验路径，按请求确认一次调用/终态/消费或退款。
3. 回退时先退 NewAPI，再退 CPA，避免仍有 v2 发送方而验证端已经不认识该类型。

当前只完成本地实现和检查，生产配置、审计开关、渠道、凭据和额度未改。
